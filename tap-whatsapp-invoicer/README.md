# tap-whatsapp-invoicer

أداة مستقلة (CLI) بلا أي علاقة بتطبيق ميار الموجود في هذا المستودع — غرضها الوحيد
هو إنشاء فواتير عبر **Tap Payments** وإرسالها للعملاء عبر **واتساب**، بحيث يمكن
لأي جلسة Claude Code تشغيلها نيابةً عنك (فاتورة مفردة أو دفعة عملاء من ملف CSV).

## ⚠️ ملاحظة مهمة قبل الاستخدام

أثناء بناء هذه الأداة كانت شبكة بيئة التطوير تحجب الوصول إلى
`developers.tap.company`، فلم يتسنَّ التأكد من **الاسم الدقيق** لحقل تفعيل
الإرسال عبر واتساب في نداء إنشاء الفاتورة. الأداة ترسل حاليًا:

```json
"notifications": { "channels": ["whatsapp"] }
```

كتخمين مبني على أن منتج "Tap Billing" يعلن دعمه لإرسال الفواتير عبر واتساب.
**قبل الاعتماد على الأداة مع عملاء حقيقيين**، جرّبها أولًا (باستخدام مفتاح
`sk_test_...` وجوالك الشخصي) وتأكد أن رسالة واتساب تصل فعليًا. إن لم تصل:

1. راجع الرد الكامل الذي تطبعه الأداة بعد كل فاتورة (JSON) — فيه غالبًا تفاصيل
   إضافية من تاب.
2. تحقق من الحقل الصحيح عبر [توثيق تاب الرسمي](https://developers.tap.company/reference/create-an-invoice)
   أو الدعم الفني لتاب.
3. عدّل القيمة بدون لمس الكود، عبر متغير البيئة `TAP_NOTIFICATIONS_PAYLOAD`
   في ملف `.env` (راجع `.env.example`).

بغض النظر عن نجاح الإرسال التلقائي عبر واتساب، ستحصل دائمًا على `url` — رابط
فاتورة تاب المستضاف — في رد كل عملية، ويمكنك مشاركته يدويًا كخطة بديلة.

## المتطلبات

- Node.js نسخة 20.6 فأعلى (لدعم `--env-file` المدمج بدون أي حزم إضافية).
- حساب **Tap Business** فعّال، ومفتاح API سري (`TAP_SECRET_KEY`) من
  لوحة التحكم: Developers → API Keys.
- تفعيل ميزة الفوترة/الإرسال عبر واتساب على حساب Tap الخاص بك (تحقق من ذلك في
  لوحة التحكم أو مع مدير حسابك في تاب).

## الإعداد

```bash
cd tap-whatsapp-invoicer
cp .env.example .env
# افتح .env وضع مفتاحك السري: TAP_SECRET_KEY=sk_test_...
```

ملف `.env` مستثنى بالفعل من git عبر `.gitignore` في جذر المستودع — **لا تضع
مفتاحك السري في أي كود أو commit**.

## الاستخدام — فاتورة واحدة

```bash
node --env-file=.env src/sendInvoice.js \
  --first-name "أحمد" --last-name "العتيبي" \
  --country-code 966 --phone 501234567 \
  --amount 250 --currency SAR \
  --description "اشتراك شهري - سبتمبر"
```

أو عبر npm script مختصر:

```bash
npm run send -- --first-name "أحمد" --country-code 966 --phone 501234567 --amount 250
```

أضف `--dry-run` لمعاينة الطلب فقط بدون إرساله فعليًا لتاب (مفيد للتجربة أو
عندما يشغّل Claude Code الأمر ويريد المستخدم مراجعته أولًا).

## الاستخدام — دفعة عملاء (CSV)

جهّز ملفًا بنفس تنسيق `customers.example.csv`:

```csv
first_name,last_name,email,country_code,phone,amount,currency,description
أحمد,العتيبي,ahmed@example.com,966,501234567,250,SAR,اشتراك شهري - سبتمبر
```

ثم شغّل:

```bash
node --env-file=.env src/sendBulk.js --file customers.csv
```

تُرسل الأداة فاتورة لكل صف مع مهلة (افتراضيًا 1500ms) بين كل طلب والتالي لتجنب
تجاوز حدود معدل الطلبات عند تاب، وتطبع نتيجة كل صف على حدة دون إيقاف الدفعة
كاملة إذا فشل صف واحد. أضف `--dry-run` لمعاينة الدفعة بدون إرسال فعلي.

## التحقق من حالة فاتورة

```bash
node --env-file=.env src/checkStatus.js <invoice_id>
```

## كيف يستخدمها Claude Code؟

بما أن الأداة عبارة عن أوامر طرفية عادية، يمكن لأي جلسة Claude Code (بصلاحية
تشغيل أوامر) أن "تتولى" إرسال الفواتير نيابة عنك — مثلاً تطلب منها:

> "أنشئ فاتورة بـ 300 ريال للعميل خالد، جواله 966512345678، وأرسلها له"

فتقوم الجلسة بتحويل ذلك إلى استدعاء `sendInvoice.js` بالمعاملات المناسبة.
تأكد أن الجلسة تعمل داخل مجلد يحتوي على `.env` بمفتاحك السري (أو أن المتغير
`TAP_SECRET_KEY` مُصدَّر مسبقًا في البيئة)، ولم تشارك المفتاح نفسه في المحادثة.

## هيكل المشروع

```
tap-whatsapp-invoicer/
├── package.json
├── .env.example
├── customers.example.csv
└── src/
    ├── tapClient.js     # نداءات REST لتاب (إنشاء فاتورة + جلب حالتها)
    ├── sendInvoice.js   # CLI: فاتورة واحدة
    ├── sendBulk.js      # CLI: دفعة فواتير من ملف CSV
    ├── checkStatus.js   # CLI: التحقق من حالة فاتورة
    └── csv.js           # محلل CSV بسيط بدون أي حزم خارجية
```

لا توجد أي تبعية على حزم npm خارجية — فقط `fetch` المدمج في Node.js.
